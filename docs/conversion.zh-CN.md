# 转换与本地缓存

[English](./conversion.md) · [简体中文](./conversion.zh-CN.md) · [返回 README](../README.zh-CN.md)

选择新的 PDF 转换由哪个服务处理，提前准备论文，或导入本地结果。本页也说明 Mktero 如何保留和清理自己的本地副本。

## 选择转换服务

打开 `设置 -> Mktero` 选择转换服务。有可用本地缓存时会跳过远程转换；新的转换需要能够访问所选服务。

| 转换服务 | 未命中缓存时，完整 PDF 发往哪里 | 需要什么 |
| --- | --- | --- |
| Mktero，默认服务 | 你的账号使用的 Mktero 托管服务 | Mktero 账号；无需 MinerU 或 Mistral 密钥 |
| MinerU 云端 | MinerU 云端 | 你自己的 MinerU API key |
| 自部署 MinerU 4.0 | 配置的本地 MinerU 服务 | 服务地址；本地 API key 可选 |
| Mistral OCR 4.1 | Mistral | 你自己的 Mistral API key |

选择 MinerU 或 Mistral 后，PDF 会发送给该服务，不再发送给 Mktero。[导入受支持的 llm-for-zotero 本地结果](#导入-llm-for-zotero-本地结果)及重新打开其已保存副本可以离线进行，无需账号或转换服务密钥，但必须启用本地缓存。

设置项见[配置](./configuration.zh-CN.md)，发送、存储和同步规则见[数据与隐私](./privacy.zh-CN.md)。

## 托管解析模型

运营方可以为托管服务使用的每个 MinerU 账号单独选择 MinerU-VLM 或 MinerU Pipeline。这是服务端的决定：扩展没有托管模型设置，下文的直连 MinerU 云端设置也不会影响它。PDF 使用稳定的解析路由；新建任务使用路由当前的模型，已有任务保留创建时的模型。

复用托管转换缓存前，Mktero 只发送 PDF 的 SHA-256、字节大小和内容类型，查询适用的解析配置。这项查询不上传 PDF，也不占转换额度。模型变化后，下次打开会查找该模型对应的结果，可能需要重新转换并上传 PDF；新增结果遵循正常额度计数。切回之前的模型时，可以复用仍保留的对应结果。

离线时可以用保留的本地内容阅读，但无法核实服务当前的模型。认证失败、目标元数据无效或不一致时会明确报错。显式本地导入仍可独立离线使用，不经过这项托管查询。

校对属于产生该次阅读的解析身份。托管 `Pipeline` 阅读不会打开为 `VLM` 保存的修订；路由切回 `VLM` 时，仍能找到 `VLM` 的校对，包括记录在更早 `VLM` 解析配置下的校对。

## MinerU 云端解析模型

使用自己的 MinerU 云端密钥时，`设置 -> Mktero` 还会提供`解析模型`：`VLM`（默认）或 `Pipeline`。它只作用于直连 MinerU 云端操作。Mktero 托管转换由服务端决定模型，本地 MinerU 服务沿用自己固定的请求，两者都不读取这个设置。

每次操作在开始时确定 MinerU 云端模型：早于本地导入检查，也早于 Mktero 加载 PDF。因此之后修改`解析模型`只影响后续操作。若同一项目已有正在运行的任务，再次打开会加入原任务，新设置既不会移动也不会取消进行中的工作。已受理的任务保留发送时的模型，不会被当作另一个模型轮询或恢复，切回该模型时可以继续恢复。按另一个模型打开同一 PDF 会为该模型另建任务。在出现该选择之前记录的待续任务属于 `VLM` 任务；首选项中无法识别的值同样按 `VLM` 处理。

两个模型各自保留本地缓存和待续任务记录。因此切换设置既不会覆盖也不会删除另一个模型已保留的结果或未完成任务：切回去仍可复用匹配的保留结果，也仍可恢复对该模型依然有效的任务。若待续任务属于另一个模型，Mktero 会报告这一不匹配，而不是按错误的模型恢复，也不会丢弃它。

Markdown 缓存身份就是解析配置本身，所以直连 MinerU 云端转换会复用同一模型此前经 Mktero 托管服务得到的本地 Markdown 条目，反向亦然。两条路径保留的 MinerU 原始结果彼此分开，只有可读的 Markdown 及其图片共享。

这项选择不会把一次阅读带到另一个模型。一个模型解析的结果不会被当作另一个模型的结果展示，`Pipeline` 阅读也不会读入在 `VLM` 阅读上保存的校对。切回 `VLM` 时，这些早先的 `VLM` 校对仍能找到，包括保存在更早 `VLM` 解析配置下的校对。图组属于它们所恢复的那份结果：命中的缓存结果会保留原有图组；仍需恢复时，Mktero 使用本地 PDF 为当前打开的模型结果恢复，且图组绝不作为校对跨模型带过去。

## 页数与大小限制

文件大小、页数、额度和服务可用性由所选转换服务决定。使用 MinerU 或 Mistral 时，请查看 [MinerU API 文档](https://mineru.net/apiManage/docs)或 [Mistral OCR 文档](https://docs.mistral.ai/studio/document-processing/basic_ocr)中的当前限制。

Mktero 托管转换和 MinerU 云端每个 PDF 最多 **200 页**。发送前，Mktero 会在本地统计页数，超出时提示并停止，不会上传。本地 MinerU 和 Mistral 不做这项页数检查。

## 托管转换日额度

服务启用限制时，新的托管转换结果会占用 UTC 自然日的文档额度。`设置 -> Mktero` 的账号面板从服务读取限额，显示已用、处理中（预占）、剩余额度，以及本地时区的完整重置日期和时间。

额度受阻时，准备窗口会保留当前项目和待办项目，已提交任务继续处理。可以选择：

- `检查额度并继续`：查询额度、重新检查本地结果是否已就绪，再显式恢复待办。剩余为 0 时也可以继续：本账号已转换过的文献可以不占新增额度获得结果；新文献会再次被拒绝，账号也再次暂停。
- `取消剩余任务`：丢弃待办，不中断在途任务。

该账号的新项目会保持暂停，直到手动恢复。列表只在本次 Zotero 会话中保留，不会在午夜自动续跑。切换账号不会迁移列表；要用另一账号或自备服务处理同一 PDF，请重新选择并提交。

本地缓存阅读、校对、导出、自备转换服务和 AI 翻译不受影响。预占、返还和结果复用的规则见[额度计数](#额度计数)。

## 批量准备 PDF

1. 选中多条文献或 PDF 附件，选择 `准备所选 Markdown`。准备整个分类时，右键分类并选择 `准备此分类及子分类的 Markdown`。
2. 分类操作包含所有层级的子分类。开始前，确认整棵分类树中去重后的 PDF 数量。
3. 在 Zotero 进度窗口中查看每一篇的进度。最小化后队列继续；`取消`会停止尚未完成的篇目。

这些操作将 PDF 加入队列，不为每篇打开阅读标签页。已有缓存或正在准备的 PDF 会跳过，也包括该附件自己可读的导入结果。一个 PDF 已导入，不代表同一父条目的其他 PDF 已就绪；只有导入选择、没有可读内容时，不会按已就绪跳过。

打开队列中的 PDF 会接入已有准备，不会重新上传。批量中的每篇未缓存 PDF，发送方式与单篇转换相同。导出已经准备好的论文，见[批量导出到 Obsidian](./references-and-export.zh-CN.md#批量导出)。

## 标签页、取消与重新解析

阅读单篇时，打开 PDF 并点击 Zotero 阅读器工具栏的 Mktero 文件图标，或在 PDF、文库条目的右键菜单中选择 `使用 Mktero 阅读 Markdown`。临时标签页会显示上传、转换和下载进度；有有效缓存时跳过远程转换。

- Mktero 标签页仅在当前会话有效，Zotero 重启后不会恢复。再次打开同一 PDF 和转换配置时，会回到上次阅读的段落。
- 关闭标签页不会停止进行中的转换，它会在后台准备窗口中继续。关闭扩展会取消进行中的转换和翻译请求。
- `重新解析 PDF` 位于阅读器的 `⋯` 菜单中。它会使用当前转换服务，可能上传 PDF；对于选定的导入结果，只有重新解析成功才会替换该附件的导入选择。

在同一个运行中的 Mktero 实例和账号会话内，PDF 字节和解析配置相同的附件会共享进行中的托管转换，关闭本地缓存时也适用。各附件保留各自的阅读状态、标题、注释、校对和图片处理。取消与强制重新解析的规则见[共享转换与取消](#共享转换与取消)。

## 导入 llm-for-zotero 本地结果

1. 确保 PDF 已在本机可用，由 llm-for-zotero 完成解析，并启用 Mktero 本地缓存。若只有同步结果 ZIP，请先用 llm-for-zotero 恢复到本地；Mktero 不直接导入该 ZIP。
2. 在 Zotero 文库中，右键一个 PDF 附件或它的父条目。发现本地候选结果后，选择 `从 llm-for-zotero 导入解析结果…`。父条目有多个候选 PDF 时，从子菜单选择目标附件。
3. 点击菜单项即开始导入：Mktero 校验结果、保存独立副本，并在正常阅读标签页中打开该 PDF。菜单检查只负责发现候选，点击后才会完整校验。

导入可以离线进行，无需账号或 API 密钥。它不上传 PDF 或结果，也不修改源缓存。取消或失败会保留此前的导入选择；导入失败、内容损坏、读取错误或取消都不会触发转换。

要换成新结果，再次导入即可。重新打开时请使用所选 PDF 自己的阅读入口：导入另一附件不会改变父条目的 `使用 Mktero 阅读 Markdown` 操作，该操作仍打开第一份 PDF。

支持的格式、离线重建和之后的阅读何时可能上传 PDF，见[支持的输入与保留副本](#支持的输入与保留副本)。

## 查看哪些条目已有 Markdown

文献列表中有一个 Markdown 列：

| 指示 | 含义 |
| --- | --- |
| 就绪标记 | 这台电脑可以用当前转换设置或该 PDF 选定的导入结果，直接打开可读的缓存 Markdown。托管转换下它只表示存在保留结果；服务当前分配的模型要等真正打开该 PDF 时才确定 |
| 旋转指示 | PDF 正在本次会话中排队或转换；该指示不会保存 |

就绪标记保存在 Zotero 配置文件中，不改变 Zotero 条目，也不同步。清空缓存会使其熄灭。切换转换服务、MinerU 服务或 MinerU 云端解析模型会改变就绪的转换缓存。托管转换下，该标记只说明存在保留结果，不会随服务端当前模型变化；后者在真正打开时才通过解析确定。选定的导入结果保留独立身份，但仅有选择记录不会标为就绪。

可以从文献列表的列选择器隐藏该列，Zotero 会记住这个选择。

## 本地缓存清理

Mktero 不会按条目数、总大小或闲置时间自动淘汰 Markdown 和 MinerU 原始结果。将条目或 PDF 附件移入 Zotero 回收站、从分类移除，都不会删除其 Mktero 数据。

后台确认已登记的 PDF 附件永久消失，且缓存没有剩余引用后，即可清理，不设额外保留期。清理前恢复附件会保护其数据。共享 PDF 会保留，包括其他文库、回收站中，甚至从未由 Mktero 打开的附件。

打开 `设置 -> Mktero -> 自动清理`，可查看保留的缓存记录数、已释放的可重建缓存、本地缺少 PDF 的附件、原因、最多十个阻塞附件的 key 和文库 ID，以及下次检查时间。完成检查后，缓存用量会刷新。`重新检查`执行相同的安全检查，不绕过保护，也不清空全部缓存。

Mktero 设置中仍可手动`清空缓存`。手动清理、损坏条目的自愈，以及配置文件所在文件系统丢失或不可用，都可能使缓存丢失；单个压缩包、文档、图片和解析资源仍受安全上限约束。完整规则见[清理范围](#清理范围)、[检查与重试](#检查与重试)和[缺失或无法核实的-pdf](#缺失或无法核实的-pdf)。

## 细节

### 额度计数

- 接受请求时预占额度，成功后计入已用；只有服务端确认最终失败或取消才释放。客户端超时或关闭标签页，不会返还仍在服务端执行的任务额度。
- 跨日完成的任务仍归属首次接受请求的 UTC 日期。
- 复用已有授权结果不重复计数；另一账号首次取得共享结果时计入该账号。这不保证失效结果日后可以无限免费重新生成。
- 观察模式只显示用量，不会宣称已执行限制。旧服务端没有额度接口时仍可正常使用。

### 共享转换与取消

- 取消一个参与者不会中断其他参与者。只有最后一个参与者离开时，才尝试取消托管任务；任务进入处理后，服务端可能拒绝取消。
- 强制重新解析会接入仍在进行的原始结果获取，包括归档保存。结果就绪后再强制重新解析，会开始新一次获取。任务活跃时已预留交接的替换操作，仍可接管随后完成的结果。
- 退出、重新登录、切换服务或 API 地址，会隔离后续托管任务。自动刷新令牌保持当前账号会话。
- 共享不会跨重启，也不会协调独立的 Zotero 进程或设备。

### 支持的输入与保留副本

受支持的本地结果需要 `full.md`，以及带有效页码、区域坐标的标准内容列表，或受支持的版面数据。必要图片需有原图、受支持的 llm-for-zotero 裁图，或 Mktero 可以从本地 PDF 安全恢复的区域。llm-for-zotero 生成裁图后移除原图，本身不代表缓存无效。

纯 Markdown、旧版散装 Markdown，以及没有区域坐标的本地 MinerU V1 内容列表均不受支持。菜单可能发现这样的候选；导入时会说明无法使用的原因。

导入后使用 Mktero 的独立副本阅读。只删除 llm-for-zotero 源缓存，仍可离线阅读。副本遵守[本地缓存清理](#本地缓存清理)规则，包括手动清理、损坏条目、文件系统和资源上限的限制。

Mktero 优先使用已保存的校对或已生成的阅读文档。若只剩保留的原始结果，会在本地离线重建文档。如果选定导入结果的本地内容**全部缺失**，之后普通的 `使用 Mktero 阅读 Markdown` 会使用当前转换服务，可能上传 PDF；导入操作本身始终只在本地进行。

新导入快照的校对、译文和阅读位置彼此独立。主动重新解析遵守[使用当前转换服务的规则](#标签页取消与重新解析)，失败时不会静默替换导入选择。

### 清理范围

| 后台清理可以删除已登记的孤立数据 | 后台清理不会删除 |
| --- | --- |
| Markdown、图片、译文、MinerU 原始结果、对应的已保存校对、PDF 文本索引和阅读位置 | Zotero PDF 原文件、笔记、注释和已保存快照 |
| 已删除附件的本地高亮、高亮分组记录、导入选择和就绪标记 | 已导出的文件和 llm-for-zotero 源缓存 |

下次读取或导入 PDF 时才登记归属，并接管可识别的旧解析配置缓存；无法确定归属的历史数据保留在磁盘上。此前已记录的永久删除适用同一清理规则，启动检查也会核对错过的通知。

引用缓存和旧版独立翻译缓存沿用原有的过期、容量规则。

### 检查与重试

- 永久删除通知合并约 **5 秒**后安排后台检查。启动约 **60 秒**后，以及 Zotero 运行期间**每小时**也会检查。
- 只有相关附件或缓存正在阅读、转换、等待写入等占用，才会延后其清理。阅读无关论文不阻塞；相关占用结束后会重新检查，不必等待下一轮小时检查。
- 先在本地核对文件大小，再对可能相同的文件计算哈希；不会下载或上传附件。
- 归属或共享引用不明、文库不可访问、归属记录损坏、扫描不完整时，相关数据会保留。扫描资源上限也可能延后清理。
- 删除失败会重试；通知延迟不代表文件一定在 5 秒内消失。不确定的检查和失败操作约在 **1、5、15 分钟，之后每 60 分钟**重试；启动或小时检查更早时会提前执行。相关 Zotero 文件或条目通知也会提前触发重试。

### 缺失或无法核实的 PDF

缺失或无法读取一个 PDF，不会中止其他附件的枚举。检查按候选缓存记录不确定性：可读取且再次核对的文件大小，即使文件内容无法读取，也能排除大小不同的候选。历史归属哈希和 Zotero 上次同步的 MD5 不会被用来假定内容不同；已确认的共享引用继续保护数据，包括回收站和其他文库。

完全缺失的 PDF 分两步处理，避免一个缺失文件永久保住无关缓存：

1. Markdown、原始转换结果和 PDF 文本索引可以重新转换重建。确认没有可读 PDF 仍共享这些数据后，即可释放。
2. 校对和阅读位置无法重建。只要附件记录本身仍在，就会保留。

仍存在但无法核实内容的文件、检查中发生变化的 PDF，以及不完整的文库扫描，都会使全部相关数据保留。恢复缺失的本地 PDF 后，下次检查才能确认它是否共享缓存内容。
