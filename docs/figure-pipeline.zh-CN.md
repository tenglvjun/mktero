# 图组恢复流程

[English](./figure-pipeline.md) · [简体中文](./figure-pipeline.zh-CN.md) · [返回 README](../README.zh-CN.md)

Mktero 不会直接把 OCR 服务返回的图片原样显示。当证据足够充分时，它会从本地 PDF 重新拼出完整的高清图组，并替换阅读流中的 OCR 片段；证据不足时，则保留服务返回的原图片和文字，而不是猜测。

## 区域恢复

图组候选由 Provider 内容块和精确的 Markdown 范围构建。只有当版面证据、页面坐标和 Markdown 范围三者一致时，才会从本地 PDF 裁切出完整图组。生成的本地 PNG 会保留 `2x2`、`4x4`、缺角、跨行和不规则排列。

图内 OCR（属于图表本身的标签和文字）只有在裁切成功后才会从阅读流移除；图注仍可选择、搜索和翻译，正文中的图表引用不受影响。本地恢复流程还会在不上传 OCR 的情况下升级兼容的缓存结果，并保留用户的校对内容。

歧义、旋转或无法验证的图组会保留原图片和文字。

## 渐进式渲染

本地 PDF 光栅化在后台 Worker 中完成，拼图过程不会阻塞阅读界面和 Zotero 其他操作，同一页有多个图组时只渲染一次。

转换完成后即可开始阅读：尚未拼好的图组显示动画占位（lucide 图片图标加旋转 loader），每拼好一个就就地替换，慢的图不会拖住其余内容。关闭阅读标签页不会停止正在进行的恢复，任务会继续并在完成后更新缓存。所有图表处理完成前，导出与保存快照保持禁用。

## 标签面板

当单张完整 PDF 图片的边界、匹配的 PDF 图注以及每个面板的像素都一致时，两家 Provider 都可以从中恢复带标签的面板。

独立的 OCR 标签行（如 `(A)`、`(B)` 及其全角形式）只有在完整图片恢复后才会从正文移除；正文引用和图注内部的标签保持原样。

## 重新合并被错位标题拆开的图组

当 PDF 文字位置、共享图注以及每张图片的像素都能验证关系时，两家 Provider 都可以重新合并被错位标题拆开的图组，向量图表也包含在内。

标题会保留在图组上方并可搜索；图片按 PDF 行序恢复，陈旧的版面标记会重建，跨整行的图片同样处理。

## 服务支持

- MinerU 的区域恢复需要受支持的详细布局元数据。
- Mistral 的像素尺寸无法确定 PDF CropBox 的原点和旋转方向，且这一点尚未独立验证，因此当前生产适配器不会执行基于坐标的区域恢复，而是保留原图片和 OCR 文字；上述基于图片证据的处理仍然适用。
- MinerU 与 Mistral 使用独立的解析配置，因此图组结果分别缓存，不会跨 Provider 复用。

## 资源上限

图组处理有明确的资源上限：页数、版面内容块、候选比较次数、裁切像素、画布内存、生成字节数和渲染时间都有上限，超出预算的内容会保留而不是裁切。图组回归语料见[开发](./development.zh-CN.md)。
