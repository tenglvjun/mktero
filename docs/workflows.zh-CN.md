# 阅读与注释工作流

[English](./workflows.md) · [简体中文](./workflows.zh-CN.md) · [返回 README](../README.zh-CN.md)

## 带来源的阅读

OCR 内容映射会把 Markdown 内容块连接到 PDF 的物理页码和区域。来源跳转和附带来源复制只在映射可靠时执行；匹配存在歧义时不会猜测位置。PDF 已有可读缓存时，选中文字会提供“在 Markdown 中打开”。来源区域唯一时会定位到对应段落；如果没有任何区域与选区重叠，但这段文字只出现在一个已缓存段落里，仍会打开该段。该段已有完整译文且当前是原文时，会切到双语，已经是译文或双语则保持当前视图。这不会发起新的翻译请求。Markdown 在隔离的 shadow root 中渲染，并使用受限的链接和图片策略。MinerU 文档会保留 PDF 原生安全 HTTP(S) 链接注释和 MinerU 提供的超链接目标，包括 URL 中的下划线；目标缺失或不安全时只显示普通文字。学术论文的图注会按常见出版商格式识别，包括紧跟在空 OCR 图片之后的 `Figure N | ...` 图注，因此正文中的图表引用在缓存文档里仍可预览。

## 脚注与文章信息

在 MinerU 结果中，PDF 页面底部的脚注会显示为灰色小字，放在该页第一个带有对应标记（上标数字、`*` 或 `†`）的段落之后。找不到标记的脚注放在该页最后一个段落之后，不会越过标题。表注和图注使用同样的样式，紧跟在表格或图片下方。脚注是普通的引用文字，可以查找、添加注释、翻译和复制。正文中的脚注标记可以点击跳到对应脚注（“跳到脚注”），脚注开头的标记可以跳回正文；这两种跳转都会记录，按 `Alt+←`（macOS 上是 `Cmd+[`）可以回到原位置。

不属于正文的文章元信息会放进折叠区块：作者单位、联系方式和贡献说明、基金、日期以及期刊首页侧栏，放在标题和作者行下方的“文章信息”里，因此第一屏只显示标题、作者和摘要。参考文献之后的作者简介放进“作者简介”，Nature 的 Reporting Summary 放进“报告摘要”。自部署的 MinerU 服务读出图表数据时（高精度档位），数据放在图表之后的“图表数据”里，是表格时按表格显示。每次打开文档时区块都是收起的。区块标题是一个按钮，可以点击，也可以用 `Enter` 或空格键操作。查找结果、注释和其他跳转指向收起的区块时，会先展开它。区块内的标题不出现在目录中。快照和 Zotero 笔记中，区块显示为加粗的区块名称加上其内容。导出 Markdown 和 Obsidian 时，内容按普通文字保留；区块标记是 HTML 注释，在 Obsidian 中不可见。

Mktero 根据版面和页面文字识别这些部分。标记印刷方式特殊时，脚注可能放在别的段落之后；不像元信息的内容会留在正文里。

## 复制公式、代码块与表格

指向行间公式或表格时，它的右上角会出现复制操作；代码块则在工具栏中提供复制。

复制公式会以标准 Markdown 放进剪贴板：用 `$$` 块包住渲染后公式对应的 TeX，包括 Mktero 为了让公式能正常排版而做的 OCR 修正。粘贴到 Zotero 笔记或能渲染 TeX 公式的 Markdown 编辑器里，都会显示为公式。过大或使用了 Mktero 拒绝渲染的命令的公式，会改为只复制其源码。已保存的快照在阅读器中打开时，其中的每个行间公式也提供同样的操作。

表格提供 `复制为 Markdown` 与 `复制为 CSV`。如果阅读器是用某段 GFM 渲染出这张表的，Markdown 操作给出的就是那段内容，粘贴回去是同一张表。论文自带 HTML 的表格，以及已保存快照里的每一张表，则会反推成管道表：`thead` 行作为表头（没有表头时提升第一行），合并单元格展开，列对齐取自单元格自身的 `align` 属性，粗体、斜体、代码、链接、公式与上下标保留其含义。

CSV 操作用逗号分隔行、单元格为纯文本：粗体、链接、公式等行内标记会还原成屏幕上看到的内容，引用保留 `[1]` 标记；单元格含逗号或引号时按 RFC 4180 加引号，表题不计入数据。当表格超出阅读器的导出预算时，复制会被拒绝而不是截断。

表格的 `复制为 Markdown` 和公式的复制操作还会把 HTML 放进剪贴板，因此粘贴到 Zotero 笔记时会保留表格或公式。用 `Cmd/Ctrl+C` 复制时，剪贴板里的文本是按阅读器所见整理的标准 Markdown：每个公式写成行内 `$…$` 或 `$$` 块，内容是阅读器排版用的 TeX；论文自带 HTML 的表格写成带公式的管道表；阅读器隐藏的页眉、页脚和页码标记不会带上。能渲染 TeX 公式的 Markdown 编辑器会显示同样的公式和表格。内容含公式或表格时还会附带 HTML，即这段内容在 Zotero 笔记里的样子，所有公式都在其中，单个字母的 `$i$` 也不例外。不含公式和表格的内容只复制文本。选区落在渲染后的公式里时复制整个公式，落在表格单元格里时复制该单元格的文字及其中的公式，跨渲染表格的多个单元格时，把这些单元格复制成一张表。过大或使用了 Mktero 拒绝渲染的命令的公式保留源码；一次复制很长、公式很多的内容时只保留 Markdown。会读取剪贴板 HTML 的应用（例如文字处理软件或浏览器里的编辑器）收到的是同一段内容，公式以 `$` 包住的 TeX 显示；要在那里得到 Markdown，请用“粘贴为纯文本”。选区菜单里的附带来源复制会把这段内容引用成 Markdown，公式保留为 Markdown 公式，并附上来源链接；粘贴到 Zotero 笔记时是一段带排版公式和可点击链接的引用。CSV 和代码的复制不变。

以上操作只读取渲染后的文档：不发送任何内容，也不会改动缓存的 OCR Markdown、校对或评论。

## 找到位置并返回

阅读区底部边缘有一条细进度条，显示读到文档的哪里。它只在文档长到需要滚动时出现，专注模式下隐藏。

从当前阅读位置跳走时，Mktero 会记下出发点，方便你回来。会被记录的跳转包括：打开引用、表格引用或图表引用；点击目录条目或注释；跟随文档内链接；以及查找。在同一次查找的多个匹配之间逐个跳转，只算一次跳转。Windows 和 Linux 上用 `Alt+←` 后退、`Alt+→` 前进，macOS 上用 `Cmd+[` 与 `Cmd+]`；两种平台的组合在阅读器里都可用，工具栏开头的两个箭头按钮效果相同。后退时会保留你离开的位置，所以可以再前进回去；后退之后如果又发生新的跳转，之前可前进的步骤会被丢弃。每个已打开的文档最多保留 50 个位置。历史不会保存：关闭标签页或替换文档（例如重新解析）会清空历史。手动滚动不会产生历史记录。

## 校对识别错误

双击已有段落、标题或 GFM 表格单元格即可编辑，然后显式保存或取消。关闭标签页、主窗口或退出 Zotero 时，仍在编辑的内容会自动保存；如需放弃，请按 `Escape` 或“取消”。在 `Manage corrections` 中还可以删除和恢复已有段落或标题。校对数据独立于转换缓存，并绑定当前 PDF 内容和所选服务的解析配置；如果已保存的校对无法读取，文档会以原始识别结果打开并显示提示，下次保存校对或重新解析时会替换这些无法读取的数据。不能插入或重排内容块，也不能添加图片或原始 HTML。保存校对后会保留当前阅读位置，继续滚动时整篇文档仍可正常显示。公式、OCR 使用美元符号包裹的引用标记和已匹配的划区文字都受到保护；需要修改划区文字时，应先删除划区。划区前后的文字仍可编辑，保存后会同步更新划区锚点，重新打开文档仍能对准原位置；如果恢复校对会改变已划区的校对文本，Mktero 会拒绝恢复。在渲染后的 GFM 表格中，含受保护内容的单元格保持只读，其他单元格仍可编辑。恢复全部校对或重新解析含校对的 PDF 时，会使用阅读器内的 Mktero 确认框；按 `Escape`、点击遮罩或使用默认聚焦的“取消”都不会改变文档。

## 从 Markdown 创建注释

可拖选标题或正文，包括紧接图文块和整行公式的标题和段落末句。

打开文档时会加载已有的 Zotero 文本高亮和下划线。拖选也可以从论文引用、图表引用或脚注标记开始；不拖动的单击仍会打开它。保存的文本与阅读器显示的一致：`$^{*}$` 这类上标标记保存为对应的符号，跨两个表格单元格的文字之间保留一个空格，链接标题不会写入。公式保存为它的 TeX，图注和表格单元格里的公式也一样；那里的高亮会显示在渲染后的公式上。被拆成超过 512 段的选区会提示无法高亮，而不会被不完整地保存。选中 Markdown 文本后可以立即创建本地注释；只有本地 PDF 文字索引能够可靠定位唯一位置时，Mktero 才会创建对应的 Zotero 注释。重复或歧义文本会保留在本地并可重试，不会被放置到猜测的位置。如果已保存的本地注释未能完整读取，Mktero 会把原文件保留在 Zotero 配置目录的 `mktero-annotations/v1` 中，另存为 `item-<id>.corrupt-<时间戳>.json`，并显示提示；仍能读取的注释会照常保留，之后也可以添加新注释。跨越 PDF 分页的选区会按页面拆成多个单页 Zotero 高亮，因此完整的 Markdown 选区仍可导航。在 Markdown 阅读器里修改其中一段的颜色或删除它，会同时作用于 Mktero 为这次选区创建的所有分段；评论仍留在写下它的那一段。注释弹窗中，评论操作是“添加评论”和“编辑评论”。Mktero 在 Zotero 配置目录的 `mktero-annotations/groups-v1` 中记录哪些分段属于同一次选区，只保存 Zotero 注释 key。与你此前在 Zotero 中已有高亮重合的分段不会被这样分组或删除；已在 Zotero 阅读器中删除的分段会被跳过。本版本之前创建的跨页高亮没有分组记录，仍然逐段修改。高亮与论文引用、表格引用或图表引用重叠时，语义引用保持更高的交互优先级；仍可从周围的高亮文本或评论标记打开注释操作。
常见的 OCR LaTeX 数学符号和简单下标会转换为 PDF 提取文本的形式；正文中被 PDF 文字层抽错的少量字符也会被容忍，因此包含公式的选区仍可定位。独立成行的公式如果其 LaTeX 无法从文字层还原，会回退到该内容块记录的 OCR 区域。段落如果在一两页之后才继续，也会按同样的方式定位，中间隔着的整页图或页脚不影响。

尚未同步到 PDF 的本地高亮显示虚线下划线。同步失败的高亮显示点状警示下划线，鼠标悬停可看到原因。

## 在阅读器旁写 Zotero 笔记

左栏有三个分段：`标题`、`图表`和`注释`。`注释`分段列出这篇论文的注释，并提供搜索、颜色筛选、跳到 Markdown 位置、`在 PDF 中查看`、删除、为本地高亮重试同步，以及`添加至笔记`。

右栏是`笔记`。它列出该 PDF 父条目下的 Zotero 子笔记，最新的在前。`新建笔记`会创建一条子笔记。点击一条笔记，会在 Mktero 标签页里用 Zotero 自己的笔记编辑器编辑它。`返回笔记列表`回到列表。`在独立窗口编辑`会打开 Zotero 的笔记窗口。在列表中右键点击一条笔记，会出现与 Zotero 笔记面板相同的菜单：`在文献库中显示`会在文献库标签页中选中这条笔记，`在独立窗口编辑`会在 Zotero 的笔记窗口中打开它，`移动到回收站`会把它移到 Zotero 回收站，之后仍可恢复。只读文库中`移动到回收站`不可用。`Mktero Markdown Snapshot` 笔记不在列表中。没有父条目的独立 PDF 没有子笔记，这一栏会说明这一点。在只读文库中，笔记以只读方式打开，`新建笔记`不可用。如果无法在标签页内显示 Zotero 的笔记编辑器，笔记会改在 Zotero 的笔记窗口中打开。Mktero 不存储笔记。这些是 Zotero 文库中的笔记条目。

`添加至笔记`出现在划词弹窗、注释弹窗，以及`注释`分段的每一条上。它把这段文字插入笔记栏里当前打开的笔记，方式和 Zotero PDF 阅读器的`添加至笔记`相同：高亮文字、一条引用和页码。在笔记里点击这条引用会打开 Zotero 的 PDF 阅读器，而不是 Mktero。它需要一条已打开的笔记，也需要 PDF 位置。尚未同步到 PDF 的本地高亮，或本地 PDF 索引无法定位的选区（找不到，或有歧义），会被拒绝并说明原因。Mktero 不会在没有来源的情况下插入。把普通选区添加到笔记不会保存高亮。

这段文字里的公式会以笔记公式插入，笔记会把它渲染出来。Zotero 的高亮里放不下公式，所以高亮在每个公式前断开、在公式后接上，行间公式单独成块。文字保留高亮颜色和回到页面的链接，公式本身没有。保存在 PDF 中的注释不变。跨页的段落、Mktero 无法在 Markdown 中定位的注释，以及文字已与位置对不上的注释，保留 Zotero 的纯文本。如果 Zotero 的笔记编辑器发生了 Mktero 无法识别的变化，这段文字会按 Zotero 自己的方式插入，公式不渲染。

`从注释添加笔记`是`注释`分段中的一个按钮。它会新建一条子笔记，写入该 PDF 除手写注释以外的全部注释，与 Zotero 的同名命令相同，并在笔记栏中打开这条笔记。笔记由 Zotero 写入；之后 Mktero 会按上述方式，把它在 Markdown 中定位到的每条注释的公式写进去，再保存一次。

选中 Mktero 标签页时，Mktero 会隐藏 Zotero 右侧的条目面板。切换到其他标签页后，该面板会恢复。Zotero 不会为 Mktero 标签页更新这个面板，因此不隐藏的话，它显示的仍是上一个标签页的论文。

哪些栏开着、它们的宽度，以及左栏选中的分段，会写入 Zotero 首选项（`extensions.mktero.readerOutlineVisible`、`readerOutlineWidth`、`readerOutlineSegment`、`readerNotesVisible` 和 `readerNotesWidth`），下一个 Mktero 标签页会沿用。窗口变窄时的自动收起不会保存。

## 使用 AI 翻译

AI 全文翻译需要用户主动触发，也不会重写原始 Markdown。Mktero 会把文章拆成受控的 Markdown 批次，保护公式、引用、链接、代码、图片和结构占位符，并最多同时执行 5 个请求。阅读器支持 `Original`、`Translation` 和 `Bilingual` 三种模式；部分结果会按内容块继续补译。

如需查询术语或复杂句子，可以在 `Original` 或 `Bilingual` 的原文侧选中文本，使用选区弹窗工具栏末尾的翻译操作；加载、结果和错误只在需要时于下方紧凑展开。使用流式 Provider 时，译文会在请求期间逐步显示，并且仍可取消；非流式 Provider 会在翻译完成后一次性显示结果。翻译成功后可以重新翻译或复制纯文本译文。`自动翻译 Markdown 选区`默认关闭；开启后，选区稳定一小段时间会自动发起一次受控请求。`Translation`、`Bilingual` 的译文侧和已保存的 HTML 快照不提供划词翻译。选区译文只显示在弹窗中，不会修改 Markdown 或评论，也不会写入全文翻译缓存。每次选区请求只会把选中文本发送给配置的 AI Provider，可能产生 Provider 费用。

译文会按照源内容、Provider、协议、模型、语言、推理强度和提示词版本独立缓存。Mktero 更新后重新读取 MinerU 结果时，文字没有变化的内容块保留原有译文，只有变化的内容块会标记为待翻译。本地 Markdown 校对删除内容块后，其他未变内容块的译文会继续保留，已删除内容不再出现于 `Bilingual` 视图。修改已翻译内容块时，其他译文保持不变，该内容块会标记为待翻译，并提示是否仅重新翻译该内容块。Mktero 通过 Vercel AI SDK Core 支持 OpenAI、Anthropic、Google Gemini、DeepSeek、阿里云百炼、Moonshot/Kimi、MiniMax，以及自定义 OpenAI 兼容或 Open Responses 服务。远程地址必须使用 HTTPS；Ollama、LM Studio 等本地回环服务可以使用 HTTP。推理强度会随已知模型变化：Zotero 启动时从 [models.dev](https://models.dev) 拉取一次目录，只保存在内存中，退出后释放。不支持思考的模型只提供 `none`；不能关闭思考的模型不会出现 `none`；其他已知模型列出其支持的档位，可能包含 `on`、`minimal` 或 `max`。未知模型或目录拉取失败时仍使用 `none`、`low`、`medium`、`high` 和 `xhigh`。推理过程不会作为译文保存。

## 浏览引用图谱

引用图谱只包含当前论文，以及能匹配到当前 Zotero 文库条目的直接引用。支持时会并发查询 Semantic Scholar、OpenCitations 和 OpenAlex。匹配只使用唯一且规范化的 DOI 或 arXiv 标识符，不使用标题；Provider 返回的元数据保存在本地。

## 从 Markdown 导入参考文献

打开引用弹窗时，Mktero 会先只检查本地 Zotero，不会立即发起网络查询。对只有标题的文献点击“导入文献”会明确触发一次受限的 OpenAlex 查询；标题、年份和作者构成唯一精确匹配时会直接继续导入。如果 Provider 的年份只相差一年，则还必须同时满足清理后的标题近乎一致且首位作者匹配，才会直接导入。其他情况只显示最多三个可信候选项，选择其中一项后继续同一次导入。完整引文噪声过多时会使用清理后的标题重试，这也支持没有 DOI 的 OpenAlex 图书记录。对于 IEEE 格式的引文，Mktero 会把成对直双引号或弯双引号中的论文标题与作者、期刊、卷期和页码分开检索。对于没有引号的会议引文，Mktero 会把论文标题与其后的 `In ... Conference`、会议录、Workshop 或 Symposium 信息分开。弹窗会列出可访问的个人库和群组库，并允许选择导入目标。只读文库仍可被选择以检查状态，但导入操作会被禁用并显示权限说明。如果其他文库中已有匹配条目，Mktero 会提供明确的“复制到所选文库”操作，不会静默创建重复条目。具有可靠 DOI、arXiv ID 或 PMID 的缺失文献会通过 Zotero 原生 translator 导入；目标文库允许文件时，还会尝试导入 arXiv 或配置的公开 PDF。即使 PDF 下载失败，元数据也会保留，并可稍后重试。弹窗顶部只保留目标文库选择器；每条文献在左侧显示状态，并在右侧显示自己的导入、重试、复制或打开按钮，所有操作都只作用于当前可见条目。

作者-年份分组引用会展示所有能够匹配的参考文献。如果 PDF 转换结果在 APA 参考文献列表中间插入了无关标题，Mktero 只会在标题后明确连续出现多条参考文献时继续解析，因此真正位于文献末尾的 Author Note 仍会终止列表。

## 保存便携快照

`Save snapshot` 会在 PDF 所属条目下创建专用的 `Mktero Markdown Snapshot` Note。Note 保存便携 HTML，图片作为内嵌附件，原始 Markdown 和来源映射作为关联附件。恢复的图表还会附带可选的 `figure-map.json`，记录页面区域、子图身份和被消费的 OCR 片段。元数据缺失或损坏不会影响 Markdown 和 PNG 的阅读，旧快照仍可打开。用户修改过快照 Note 后，Mktero 不会静默覆盖。没有父级文库条目的独立 PDF 无法保存快照。

## 查看哪些条目已有 Markdown

文献列表有一个 Markdown 列。标记表示这台电脑可以用当前转换设置直接打开该 PDF 的缓存 Markdown。旋转指示表示这篇 PDF 正在本次会话中排队或转换，不会被保存。清空缓存、结果过期，或切换 Provider、MinerU 服务后，完成标记会熄灭。它不会同步，也不会修改 Zotero 条目。可以在文献列表的列选择器中隐藏该列，这个选择会被记住。

选中多条文献或 PDF 附件，选择 `准备所选 Markdown`；右键一个分类，选择 `准备此分类的 Markdown`。这两项都会开始解析，不打开阅读标签，去重后全部加入队列。分类操作只包含该分类自己的条目，不包含只属于子分类的条目。右键单篇仍然是阅读。已有缓存或已在准备中的会跳过。准备过程不会打开阅读标签。Zotero 进度窗口列出每一篇；最小化后队列继续，取消会停止尚未完成的篇目。打开其中一篇会接入已有准备，而不是重新上传。关闭正在转换的标签页不会取消转换，它会转入后台队列。

## 导出 Markdown

`导出 Markdown` 会打开系统文件夹选择窗口。选择文件夹 `A`、论文标题为 `B` 时，Mktero 会创建 `A/B/B.md`，并将提取图片写入 `A/B/assets/`，同时更新 Markdown 中的图片路径。如果 `B` 已存在，则创建 `B-2` 等带序号的目录及对应的 `B-2.md`，不会覆盖已有导出。在 Windows 上，过长的标题会被缩短，使文件夹、Markdown 文件和写入时的临时文件都低于 260 字符的路径上限。Obsidian 库内的导出也遵守这个上限。在大小写不敏感的文件系统上发生图片名冲突时，Mktero 会为图片添加序号并同步更新 Markdown 引用，避免不同图片互相覆盖。导出内容不包含译文或双语阅读视图，也不会自动导出。

## 导出到 Obsidian

`导出到 Obsidian` 写入原文，不跟随当前打开的阅读视图。每种已经完整保存的译文单独再写一份：论文名为 `B` 时，原文仍是 `B`，简体中文译文是 `B - chinese`。其他语言同样处理，例如 `japanese`、`spanish`。未完成的译文和双语对照不会导出。`导出 Markdown` 仍然只保存当前正在阅读的视图。第一次会要求选择包含 `.obsidian` 的库文件夹，之后沿用该库。可以在设置里更改库。笔记固定写入库内的 `Mktero` 文件夹，以免盖住其他插件生成的文献笔记。

论文标题为 `B` 时，结果是 `<库>/Mktero/B/B.md`，图片在 `<库>/Mktero/B/assets/`，使用普通的相对路径链接。图注写在图片下面，不放进图片的 alt 文本，因为 Obsidian 遇到方括号就不会渲染这张图片。YAML frontmatter 包含标题、作者、年份、DOI、标签、`zotero://` 链接和 Zotero 条目身份。只有 Extra 里已经有 Better BibTeX citation key 时才会写入 `citekey`。同一条目再次导出会更新这篇笔记，即使标题变了也一样。如果笔记在 Obsidian 里被改过，或文件属于另一条目，Mktero 会先询问再覆盖。它不会删除你后来放进 `assets/` 的其他文件。库的跨设备同步仍由 Obsidian Sync、iCloud 或 git 负责，Mktero 不参与。

### 批量导出

条目菜单的 `导出所选 Markdown 到 Obsidian` 只在所选文献里至少有一篇已经转好时出现，判断和文献列表的 Markdown 列相同。只选中一篇时，有 Markdown 才显示，并出现在阅读旁边，不替换阅读；没有则不显示。选中多篇时，一篇都没有就不显示，至少有一篇才显示。右键一个分类时，`导出此分类的 Markdown 到 Obsidian` 同样只在该分类自己的条目里至少有一篇已转好时出现。范围与 `准备此分类的 Markdown` 相同：只包含该分类自己的条目，不包含只属于子分类的条目。

只导出已经转换好的 Markdown。缓存未命中不会开始 OCR 或转换。一个 Zotero 父级条目对应一篇笔记。同一条目有多份已转换的 PDF 时，只导出第一份有缓存的，其余跳过。

整批只解析一次库。如果还没有保存库，会询问一次；取消这次选择不会写入任何文件。笔记仍写入库内的 `Mktero` 文件夹。Mktero 不参与该库的同步。Mktero 以前写过、且没有在 Obsidian 里改过的笔记会直接更新，不再询问。在 Obsidian 里改过的笔记，或属于另一条目的文件，会先跳过，整批结束后再询问一次。取消会停止尚未开始的篇目，已经写入的文件不会回滚。这不是账户功能，也不会自动同步。
