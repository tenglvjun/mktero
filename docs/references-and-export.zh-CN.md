# 参考文献与导出

[English](./references-and-export.md) · [简体中文](./references-and-export.zh-CN.md) · [返回 README](../README.zh-CN.md)

检查并导入论文的参考文献，浏览文库中的引用关系，再保存快照或导出带图片的 Markdown。导出的 Markdown 包含已保存的校对。

## 从 Markdown 导入参考文献

1. 打开引用弹窗。Mktero 会先检查本地 Zotero 中是否已有文献，不会立即发起网络查询。
2. 从可访问的个人库和群组库中选择目标文库。弹窗顶部只有文库选择器；每条参考文献左侧显示状态，右侧提供自己的操作。
3. 对目标文献选择`在 Zotero 中打开`、其他文库已有时的`复制到所选文库`，或缺失时的`导入文献`。导入时也可以附带公开 PDF。

对于只有标题的文献，`导入文献`会显式发起受限的 OpenAlex 查询。标题、年份和作者构成唯一匹配时会直接导入，否则最多提供三个可信候选供选择。年份容差和引文解析见[参考文献匹配](#参考文献匹配)。

只读文库仍可选择来检查状态，但导入操作会禁用并显示权限说明。PDF 下载失败会保留已导入的元数据，可以用`重试 PDF`再次获取附件。从其他文库复制条目需要显式操作，Mktero 不会静默创建重复条目。

## 浏览引用图谱

点击阅读器工具栏右侧的引用图谱按钮；论文有 GitHub 按钮时，它在 GitHub 旁边。图谱包含当前论文，以及能匹配到**当前 Zotero 文库**条目的直接引用。专注模式会隐藏这个按钮。

支持时，Mktero 会通过 Semantic Scholar、OpenCitations 和 OpenAlex 并发查询 DOI 与 arXiv 标识符。匹配必须使用唯一且规范化的标识符，不使用标题；服务返回的元数据保存在本地。

图谱的论文详情中，`使用 Mktero 打开`会按与`使用 Mktero 阅读 Markdown`相同的流程，打开该论文的第一份本地 PDF 附件。

## 保存便携快照

`保存快照`、`导出 Markdown`和`导出到 Obsidian`共用工具栏的`保存与导出`菜单，即 `⋯` 前面的分享按钮。阅读区宽度为 **680px 或更窄**时，同样的三个操作会移到 `⋯` 中。从 PDF 恢复图表期间，保存与导出入口和操作保持可见但不可用；专注模式会隐藏入口。

选择`保存快照`，会在 PDF 的父条目下创建专用的 Zotero 笔记 `Mktero Markdown Snapshot`。笔记包含便携 HTML，图片作为内嵌附件，原始 Markdown 和来源映射作为关联附件。

没有父级文库条目的独立 PDF 无法保存快照。如果你编辑过快照笔记，Mktero 不会静默覆盖。可选的图组元数据和旧版快照支持见[快照附件](#快照附件)。

## 导出 Markdown

1. 切换到要保存的阅读视图：`原文`、`译文`或`双语`。
2. 在`保存与导出`中选择`导出 Markdown`（窄阅读区在 `⋯` 中），然后在系统文件夹选择窗口中选择目标目录。
3. 选择文件夹 `A`、论文标题为 `B` 时，结果是 `A/B/B.md`，提取图片位于 `A/B/assets/`。Mktero 会更新 Markdown 中的图片路径。

这个操作导出当前正在阅读的视图，不会自动执行。已有导出不会覆盖：如果 `B` 已存在，会创建 `B-2` 等带序号的目录及对应的 `B-2.md`。Windows 路径和图片重名的处理见[文件与路径规则](#文件与路径规则)。

## 导出到 Obsidian

选择`导出到 Obsidian`，将原文 Markdown 写入本地库。这个操作不跟随当前阅读视图，而是保存原文，并把每种已完整保存的译文单独写在旁边。未完成的译文和双语阅读视图不会导出。

第一次导出时，选择包含 `.obsidian` 的库文件夹，之后会沿用该库。需要时可在 Mktero 设置中更改库。笔记固定写入库内的 `Mktero` 文件夹，不会替换其他插件生成的文献笔记。

论文名为 `B` 时，原文是 `<库>/Mktero/B/B.md`，图片在 `<库>/Mktero/B/assets/`，使用普通相对路径链接。简体中文译文命名为 `B - chinese`；其他语言采用同样的命名方式，例如 `japanese`、`spanish`。若只想保存当前阅读视图的单份 Markdown，请用[导出 Markdown](#导出-markdown)。

同一 Zotero 条目再次导出会更新它的笔记，即使标题变化也一样。如果笔记在 Obsidian 中被编辑过，或文件属于另一条目，覆盖前会先询问。Mktero 不删除你后来放入 `assets/` 的其他文件；Obsidian Sync、iCloud 或 git 可以同步库，Mktero 不参与同步。

### 批量导出

1. 选中条目，选择`导出所选 Markdown 到 Obsidian`；或右键分类，选择`导出此分类及子分类的 Markdown 到 Obsidian`。只有所选项目或分类树中至少有一份 PDF 已有可读 Markdown 时，才显示这些入口，判断与 Markdown 列相同。
2. 分类范围与`准备此分类及子分类的 Markdown`相同，包含所有层级的子分类。开始前确认去重后的 PDF 总数和其中已有 Markdown 的数量；只导出就绪内容，批次报告会列出其他 PDF 的状态。
3. 如果尚未保存库，只需选择一次。取消选择不会写入任何文件。批次进行中点击`取消`，会停止尚未开始的篇目；已经写入的文件不会回滚。

只选中一个条目时，有就绪 Markdown 才会在阅读旁显示导出，不替换阅读；所选项目都没有就绪 Markdown 时，不显示导出。一份父条目对应一篇笔记：有多份已转换 PDF 时，导出第一份有缓存的，其余跳过。

缓存未命中不会启动 OCR 或转换。批量导出不是账号功能，也不是自动同步。已有文件的处理见[批量更新与冲突](#批量更新与冲突)。

## 细节

### 参考文献匹配

对于只有标题的文献，标题、年份和作者构成唯一精确匹配时会直接导入。服务返回的年份只差 **一年**时，还必须满足清理后的标题近乎一致且首位作者匹配，才能直接导入。其他结果最多提供**三个**可信候选；选中后继续同一次导入。

完整引文噪声过多时，会用清理后的标题重试查询。没有 DOI 的 OpenAlex 记录（例如图书）也可查询。解析引文时，会将标题与周围的元数据分开：

- IEEE 格式中，成对直双引号或弯双引号里的论文标题，与作者、期刊、卷期、页码分开检索。
- 没有引号的会议引文中，论文标题与后续的 `In ... Conference`、会议录、workshop 或 symposium 信息分开。

缺失文献有可靠 DOI、arXiv ID 或 PMID 时，通过 Zotero 原生 translator 导入。已确认且只有 OpenAlex 标识符的记录（包括图书），直接使用受限的元数据创建。目标文库允许文件时，还会尝试获取 arXiv 或配置的公开 PDF；下载失败也保留元数据。

作者—年份分组引用会解析所有匹配的参考文献，包括 ACM/natbib 方括号形式，例如 `Lewis et al. [2020]` 和 `[Kirkpatrick et al., 2017; Wei et al., 2026]`。如果转换在 APA 格式的参考文献中间插入了无关标题，只有标题后明确连续出现多条参考文献时，才继续解析列表。真正的作者说明（Author Note）仍会终止列表。

### 快照附件

恢复的图表可以附带可选的 `figure-map.json`，记录页面区域、子图身份和已消费的 OCR 片段。元数据缺失或无效，不会妨碍阅读已保存的 Markdown 和 PNG。旧版快照仍可打开。

### 文件与路径规则

在 Windows 上，过长标题会被缩短，使文件夹、Markdown 文件和写入时的临时文件都低于 **260 字符路径上限**。Obsidian 库内也适用这个上限。

在大小写不敏感的文件系统上，冲突的图片名会添加序号，Markdown 引用也会同步更新。不同图片不会互相覆盖。

### Obsidian 排版与元数据

图注写在图片下方，不放进 alt 文本：Obsidian 遇到 alt 文本含方括号的图片时，不会渲染该图片。

YAML frontmatter 包含标题、作者、年份、DOI、标签、`zotero://` 链接和 Zotero 条目身份。只有 Extra 中已包含 Better BibTeX citation key 时，才会写入 `citekey`。

### 批量更新与冲突

整批只解析一次库，笔记仍写入其 `Mktero` 文件夹。Mktero 以前写过且未在 Obsidian 中编辑的笔记，会直接更新，不再询问。

在 Obsidian 中编辑过的笔记，或属于另一条目的文件，会在批次中先跳过。批次结束后，Mktero 会对这些冲突统一询问一次。
